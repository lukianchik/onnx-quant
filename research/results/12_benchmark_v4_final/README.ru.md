- Progressive-Global: среднее по восьми модельным медианам худшего относительного MSE = 0.501051, то есть снижение 49.89%; 8/8 моделей улучшены не менее чем на 5%, без увеличения размера относительно MinMax. 23/24 запусков имели строго меньший худший MSE; один откат к MinMax. На всех 24 наблюдениях test и заданный shift не хуже MinMax по MSE. Это не гарантия будущих данных.
- Progressive: 0.544426, снижение 45.56%, 6/8 моделей с выигрышем >=5%, суммарная оценка подготовки 496.35 с против 829.09 с у Progressive-Global. Global добавляет около 7.97% относительного снижения агрегированной ошибки, но примерно 67% стоимости; это оценка replay, не реальный end-to-end benchmark.
- FullBank-Robust: 0.544649 при 1357.21 с. Progressive достигает практически той же агрегированной ошибки при оценочной стоимости на 63.4% ниже. Single-Robust — 0.643458 при 250.12 с; полезен для быстрого режима. Astra-Adaptive 0.627700 при 711.29 с, уступает Progressive и по качеству, и по оценочной стоимости. Single-Dev не прошёл gate (shift у autoencoder и multi_output).
- Глобальный поиск особенно полезен в regression (1.000 -> 0.747) и MiniLM (0.988 -> 0.906). На EfficientNet-B0 выигрыш над Progressive мал. SDR самостоятельно лучше PG на MiniLM по медиане test, но не гарантирует устойчивость по всем запускам; универсальная политика — компромисс, не минимум для каждой модели.
- На EfficientNet agreement FP32: MinMax 85.16%, Progressive 94.14%, Progressive-Global 93.95%. MSE и agreement не тождественны. MLP seed 731: падение accuracy на 0.278 п.п. к MinMax, в пределах gate. LSTM квантован только выходной Gemm.
- 396/408 конфигураций ok; 12 skip V2 на autoencoder, regression, MiniLM, multi_output; 0 ошибок заданий. 533/534 адаптеров прошли проверку. Один `latent_W` (autoencoder, seed 123) пропущен из-за расхождения FP32 семантики; причина расхождения требует отдельного исследования.
- Веса INT8 хранятся с FP32-масштабами и DQ. Все сравниваемые политики имеют одинаковый размер в рамках model/seed; ускорение инференса не доказано. EfficientNet на CUDA в этом окружении медленный, cuDNN DEFAULT/fallback, поэтому замер не является сравнением аппаратных INT8-ядер.

## Методика и ограничения

Профиль final: fit 128, dev 96 (local 48, search 24, check 24), test до 512, rows 512, cap 128 каналов на группу, max 4 глобальных слоя, batch 8, 2 CPU threads/worker. Малые наборы ограничивают фактические числа: Diabetes 58/15/7/8/89, Digits test 360. Смотрите splits.csv. Test фиксирован по seed, метрики не используются внутри выбора кандидатов (по проверенному коду); выбор продуктового режима по итогам v4 означает, что для следующей окончательной оценки нужен новый holdout. Политики replay: полный банк строился заранее; prepare_s включает оценку выбранных построений и измеренный replay, не общий wall clock и не калибровку. На момент эксперимента ленивое построение кандидатов ещё не оценивалось. Сравнение с GPTQ/AdaRound/COMQ отсутствует, научная новизна не доказана. Полные журналы и массивы ошибок не включены в публичный набор; веса квантованных моделей не распространяются. Этот отчёт фиксирует состояние исследовательского стенда до интеграции v4 в приложение.

## Выбор продуктовых режимов

По результатам v4 выбраны Progressive (Balanced), Progressive-Global (Quality), Single-Robust (Fast) и MinMax (Standard и fallback). FullBank-Robust и Astra-Adaptive остаются исследовательскими вариантами. Для независимой оценки продуктовой реализации необходимы новые модели и отложенные данные, не использованные при выборе порогов.
