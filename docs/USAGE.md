## Установка и разработка

Требуются Docker и Docker Compose; на Windows — Docker Desktop с Linux-контейнерами. Запустите из корня репозитория:

```sh
docker compose up -d --build quantlab
docker compose exec -T quantlab python -m pytest -q -p no:cacheprovider tests
```

Откройте [127.0.0.1:7860](http://127.0.0.1:7860). Первая сборка загружает зависимости, BERT-Tiny и SST-2 из внешних источников; она может занять продолжительное время. Модели и данные в Git не включены. На Linux каталог `data` должен быть доступен для записи UID/GID контейнера (по умолчанию 1000:1000).

Для разработки с уже собранным образом:

```sh
docker compose -f compose.yaml -f compose.dev.yaml up -d --no-build quantlab
docker compose -f compose.yaml -f compose.dev.yaml restart quantlab
```

Исходники монтируются с хоста; демоматериалы используются из образа. Пересборка нужна при изменении зависимостей или образа.

## Как выбрать режим

| Режим | Какие данные нужны | Что делает |
| --- | --- | --- |
| Standard · MinMax | Необязательный JSON для измерения ошибки | Поканально квантует веса |
| Fast · Single-Robust | От 5 пакетов | Проверяет один локальный вариант на слой |
| Balanced · Progressive | От 5 пакетов | Последовательно проверяет варианты до порога выигрыша или исчерпания бюджета |
| Quality · Progressive-Global | От 6 пакетов | Дополнительно проверяет сочетания вариантов на отдельной выборке |

Все четыре режима сохраняют веса в INT8, деквантуют с FP32-масштабами через `DequantizeLinear` и для исходных FP16-весов добавляют `Cast` в FP16. Нужен стандартный opset ≥ 13. Поддерживаются MatMul/Gemm с постоянной матрицей FP32/FP16 и Conv с ядрами для 1–3 пространственных измерений, включая групповые свёртки. Веса, используемые несколькими операторами или являющиеся входами/выходами графа, пропускаются. Для адаптивных режимов нужна также локальная проверка активаций. Поиск выполняется в FP32, финальное качество проверяется на реальном экспортированном графе. FP16 требует поддержки исходных операторов CPU-провайдером ONNX Runtime. Исторические JSON-ключи `fp32`/`FP32` и `fp32_size_mib` обозначают исходную модель для совместимости; типы весов указаны в `source_dtype`, а покрытие считается по всем FP32/FP16-инициализаторам. Если на отложенных пакетах ни один численный выход не улучшился или выросла ошибка другого выхода, сохраняется MinMax для тех же проверенных слоёв.

## От модели до отчёта

1. На вкладке **Модель** выберите источник и нажмите **Проанализировать**. В деталях графа доступны имена, типы и формы входов.
2. На вкладке **Квантование** выберите режим. Для загруженной модели калибровка — JSON-массив пакетов вида `[{"input": [[1.0, 2.0, 3.0]]}]`. Один объект соответствует одному вызову модели. Для BERT-Tiny доступны 256 калибровочных текстов SST-2 train. Тексты объединяются в пакеты по 16. Скачайте ONNX и JSON-отчёт с результатом.
3. На вкладке **Проверка** запустите модель на одном примере. На вкладке **Датасет** сравните обе модели. Для BERT-Tiny по умолчанию используются 872 размеченных текста SST-2 validation. Можно подать CSV с колонками `text,label` или JSON/JSONL. Для своей модели используйте записи вида `{"inputs":{"input":[[1,2,3]]},"label":1}`, по одному примеру в пакете. Для JSON оберните записи в массив.

Размер датасета — до 8 МиБ и 2000 примеров. Метки необязательны и должны присутствовать либо у всех примеров, либо ни у одного. Для классификаторов с метками отчёт содержит Accuracy, macro F1 и матрицу ошибок. При числе классов свыше 256 сохраняются только ненулевые ячейки. Задержка измеряется за один проход.

Модель и отчёты каждого запуска сохраняются отдельно в `data/runs/`. Демоданные готовит `scripts/prepare_demo.py`. Исследовательские материалы находятся в [research/](../research/README.md).

## Структура кода

- `app.py` — точка входа Docker; `quantlab/ui/` — рабочая область, обработчики событий и HTML-сводки.
- `quantlab/core.py`, `engine.py`, `runtime.py`, `inference.py`, `evaluation.py` — прикладные операции над ONNX, запуск и оценка.
- `quantlab/weight_only/` — алгоритмы, адаптеры графа и политики поиска.
- `assets/theme.css` — оболочка Gradio; `assets/components.css` — изолированные HTML-сводки.

## Автоматические проверки

[GitHub Actions](https://github.com/lukianchik/onnx-quant/actions/workflows/ci.yml) запускает тесты на Linux с Python 3.13, включая синтетические ONNX-модели. Проверка встроенной BERT-Tiny пропускается без демоданных; для неё используйте Docker.

## Ограничения

- Автономные файлы ONNX до 256 МиБ; внешние файлы весов не поддерживаются.
- Исполнение на CPU; бюджет поиска оценивает объём вычислений, а не задаёт жёсткие ограничения времени или памяти.
- Приложение не является песочницей для недоверенных моделей. См. [безопасность](../SECURITY.md).

### Синтетическая FP16-демонстрация

В окружении с `numpy` и `onnx` выполните `python scripts/prepare_fp16_demo.py`. В `test-models/fp16-demo/` появятся ONNX-модель, калибровка, один вход и независимый набор оценки. Метки сгенерированы исходным линейным классификатором; Accuracy в этом примере измеряет воспроизведение его решений, а не качество на реальной задаче.
